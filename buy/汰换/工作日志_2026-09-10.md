## 三、ECO 库存爬虫修复（两起独立故障）

### 1. Cookie 通道回归（代码 bug）

- **现象**：自动爬取库存失效
- **根因**：`inventory_fetcher.refresh_inventory()` 直接读 `config.py` 硬编码旧 cookie，**绕过了 user_settings 覆盖通道** → GUI/Playwright 保存的新 cookie 爬虫拿不到 → 登录态失效爬 0 件
- **修复**：走 `eco_web_api._normalize_cookies(None)` 统一通道（user_settings > config）+ 爬取前 `try_refresh_login_via_api` 自动续期 loginToken（实测续期成功并写回）
- **教训**：所有 ECO web 调用必须走统一通道，禁止直接 import config 常量

### 2. Selenium 依赖冲突（环境 bug）

- **现象**：`ImportError: cannot import name 'WebSocketApp' from 'websocket'`
- **根因**：selenium 4.47 需要 `websocket-client`，但用户目录装了**同模块名**的 gevent 版 `websocket 0.2.1`（gerapy 依赖），且用户目录优先级高于 Anaconda → 遮蔽
- **修复**：卸载 `websocket 0.2.1`（pip 卸载残留用 `shutil.rmtree` + onerror chmod 强删）→ import 解析回 Anaconda 的 `websocket-client 1.8.0`
- **注意**：gerapy 因此不可用（如需用要单独建环境）

## 四、Buff 查询"登录态已过期"误报修复

- **现象**：查询购买 GUI 正常，自动汰换里 Buff 全挂，报"登录态已过期"
- **真相**：两个面板共享同一个后台 Buff 浏览器，差异只是**时机**——Playwright 弹出的 Edge 窗口某时刻死了（被手动关/crash），之后 `new_page()` 秒抛 `context has been closed`
- **根因（两连 bug）**：
  1. `buff_browser_query._do_query` 把 closed 异常 catch 后 `return None`，而 None 被定死解释为"登录过期"→ **误报**
  2. 异常被吞 → `_submit_to_worker` 的 closed→自动重启→重试机制**永远不触发**
- **修复**：两处 `new_page` 失败（主循环 + 无磨损重试分支）改为向上 raise，让既有重启机制自愈（persistent 登录态保留，重启后免登录）
- **效果**：关掉 Playwright Edge 窗口后下一次查询自动拉起浏览器恢复；只有 sell_order 真返回 Login Required 才提示刷新登录
